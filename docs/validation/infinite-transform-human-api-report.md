# Infinite processes, transforms, and TeX-first API validation

## Technical summary

This increment establishes a fail-closed TeX-to-generation path on the existing
Mathematical IR. It adds evidence-bearing function properties, finite lowerings
for infinite processes, transform contracts, high-recall provider retrieval,
typed unification, and bounded authorized rewrite search. Generated Python is
not certified from its plan: a second pass through the existing Python AST
frontend is required.

No chart is used because the evidence consists of exact status counts and
release-gate assertions rather than a trend, distribution, or multi-dimensional
relationship; audit tables and machine-readable JSON are the less misleading
surface.

## Scope and definitions

The verification unit is a canonical Mathematical IR expression. `DECLARED`,
`DERIVED`, `CONTRACT_VERIFIED`, `KERNEL_VERIFIED`, and `UNRESOLVED` evidence are
separate. Infinite source generation means a finite partial sum/product or other
explicit discretization; emitting an actually infinite loop is forbidden.

Retrieval recall counts whether the expected provider appears within the ranked
budget. It does not count as mathematical acceptance. False acceptance counts an
adversarial semantic mismatch that reaches an exact/transformed verified state.

## Implemented evidence chain

```text
TeX / Builder / canonical expression
→ MathSurfaceAST + SourceOrigin
→ notation resolution
→ canonical Mathematical IR
→ function/domain/convergence analysis
→ finite truncation or discretization
→ broad whole/subexpression retrieval
→ ranked budget
→ typed unification / bounded authorized rewrite
→ strict provider selection
→ source generated, unverified
→ independent frontend extraction
→ canonical re-comparison
```

## Existing assurance remains intact

The deterministic existing self-audit still reports 192 exact round trips, 264
equivalents under explicit assumptions, 12 unresolved cases, and zero semantic
divergences. It detected 252/252 semantic mutations and accepted 120/120
metamorphic alpha-renames. A private research-scale read-only rerun covered 20+ projects, 170+ source
files, and 40k+ lines. Detailed corpus metrics remain private; source parse and Mathematical IR extraction
91.35%, library-contract resolution 100%, and all seven mutations that reached
an audited numeric slice were detected. E: critical false acceptance remained 0.

## Defect burn-down

The versioned ledger now contains 18 findings: all 18 are `VERIFIED_FIXED`, with
zero deferred and zero open critical false-acceptance findings. This increment
found two medium generation-round-trip defects. Redundant `int` wrappers around
already-integral Python loop bounds were removed, and project default output
selection now delegates returned loop accumulators to the function-scoped Python
frontend instead of returning only the initializer.

## Safety findings

Domain-conditioned identities such as `exp(log x) = x` require positive-real
evidence. Implicit Einstein notation is rejected unless explicitly enabled.
Unknown convergence stays unresolved, and term magnitude is not presented as a
certified tail bound. FFT is an algorithm for the DFT layer, not an approximation
claim; numeric reordering and error remain execution metadata.

## Limitations and next actions

The TeX grammar is intentionally bounded, convergence analysis covers only a
small safe theorem set, and most broad registry entries are metadata until their
executable rewrite and proof replay are implemented. Specialized external
provider source can be emitted only after strict candidate matching and usually
remains unresolved until the existing library contract frontend can independently
recover the same mathematics. General CAS saturation, analytic continuation,
complex branch-cut automation, GPU kernel proof, and a global provider optimizer
remain out of scope.
